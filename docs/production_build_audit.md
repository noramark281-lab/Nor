# تدقيق مواءمة `Nor.zip` وإصدار Android الإنتاجي

## المصدر المرجعي

تم العثور على `nor.zip` في جذر المستودع واستخراجه إلى مساحة فحص معزولة بعد التحقق من المسارات. يحتوي الأرشيف مشروع Flutter الكامل، بما فيه `pubspec.yaml` وبنية Android وiOS وWindows ومصدر `lib/`. تتطابق ملفات Flutter المشتركة مع النسخة الحالية من المستودع؛ الفروقات التي وُجدت تقتصر بصورة أساسية على بعض ملفات الويب والأيقونات. لذلك سيُعتمد مصدر Flutter الموجود في الجذر، وهو نفس المصدر المرجعي للأرشيف، مع الإبقاء على تغييرات الأيقونات الحالية.

## مشكلات يجب تصحيحها قبل إصدار موثوق

| المجال | الوضع السابق | المعالجة المطلوبة |
| --- | --- | --- |
| إجراءات البناء | توجد عدة workflows متداخلة بوسوم إصدار ومسارات نشر مختلفة، وبعضها يبني الويب وWindows ويعرقل إصدار Android. | إبقاء مسار إصدار Android واحد واضح وموحد، مع تعطيل التدفقات المتكررة عن التنفيذ التلقائي. |
| توقيع التطبيق | التدفقات القديمة تنشئ مفتاحاً احتياطياً عند غياب الأسرار، ما يغيّر هوية التوقيع من بناء إلى آخر. | اشتراط مفتاح توقيع ثابت محفوظ كأسرار للمستودع، مع إيقاف البناء إذا غاب. |
| أسرار MEXC | الإعداد السابق يسمح بتمرير مفاتيح MEXC كتعريفات بناء داخل ملف التطبيق. | منع تضمين مفاتيح MEXC في APK؛ تحفظ المفاتيح على جهاز مالك الحساب فقط. |
| أمان التخزين | مدير مفاتيح API يستخدم `SharedPreferences` لتخزين مفاتيح الوصول والسر. | استخدام `flutter_secure_storage` على Android Keystore بدلاً من التخزين النصي. |
| تنفيذ الأوامر | التطبيق يستخدم مساراً قديماً `order/submit` ومعلمات نصية، بينما الوثائق الحالية تذكر `POST /api/v1/private/order/create` ومعلمات رقمية. | تحديث المسار، المجال الأساسي، تعيين الجوانب/الأنواع الرقمية، والتحقق من حقل `success` و`orderId` قبل عرض النجاح. |
| سلوك تجريبي | بعض المعالجات تولّد معرفاً محلياً أو تعرض نجاحاً دون تأكيد أمر حقيقي. | عدم إنشاء سجل «ناجح» أو رسالة نجاح إلا بعد استلام تأكيد MEXC الصحيح. |

## وثائق MEXC المرجعية

توضح وثائق MEXC الرسمية أن عنوان Futures API الحالي هو `https://api.mexc.com`، وأن نقاط النهاية الخاصة تحتاج رؤوس `ApiKey` و`Request-Time` و`Signature`. وتؤكد الوثائق أن أمر العقود يُنشأ عبر `POST /api/v1/private/order/create`، وأن نجاح العملية يتطلب `success: true` و`data.orderId` في الاستجابة.

> لا تُستخدم هذه الملاحظات كتوصية تداول أو ضمان للربح؛ هدفها تصحيح التكامل البرمجي وأمان الإصدار فقط.
